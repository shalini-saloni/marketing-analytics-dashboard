## Installation

### Prerequisites
- Node.js 18+
- MySQL 8.0+
- Python 3.8+ (for Part A; to generate `summary_data.json`)

### Step 1 — Clone & Install

```bash
git clone <your-repo-url> marketing-analytics-dashboard
cd marketing-analytics-dashboard/backend
npm install
```

### Step 2 — Set Up Environment

`.env` contents:
```
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_password
DB_NAME=marketing_analytics
PORT=3000
```

### Step 3 — Database Setup

```bash
# Log in to MySQL and run the schema
mysql -u root -p < ../database/schema.sql
```

### Step 4 — Generate `summary_data.json` (Part A)

```bash
cd ..
pip install pandas numpy
python spend_analysis.py marketing_spend_data.csv
cp summary_data.json backend/
```

### Step 5 — Import Data into MySQL

```bash
cd backend
node scripts/importData.js summary_data.json
```

### Step 6 — Start the Server

```bash
npm start
# or for development with auto-reload:
npm run dev
```

The server starts at **http://localhost:3000**  
The dashboard is served at **http://localhost:3000** (frontend/index.html)

## API Endpoint Documentation

### `GET /api/summary`
Returns overall performance KPIs.

**Response:**
```json
{
  "total_spend": 46303442.90,
  "total_revenue": 166979422.66,
  "total_conversions": 760490,
  "overall_roas": 3.6100,
  "overall_cpa": 60.89,
  "overall_cpc": 60.89
}
```

---

### `GET /api/channels`
Returns all channels sorted by ROAS by default.

**Query Parameters:**
| Param | Values | Default |
|-------|--------|---------|
| `sort_by` | `roas`, `total_spend`, `total_revenue`, `total_conversions`, `cpa`, `cpc` | `roas` |
| `order` | `asc`, `desc` | `desc` |

**Response:**
```json
{
  "channels": [
    {
      "id": 1,
      "name": "Email",
      "total_spend": 1764078.73,
      "total_revenue": 12833973.13,
      "total_conversions": 229747,
      "roas": 7.28,
      "cpa": 7.68,
      "cpc": 0.54,
      "avg_ctr": 5.50,
      "avg_cvr": 7.07
    }
  ]
}
```

---

### `GET /api/monthly`
Returns monthly performance records.

**Query Parameters:**
| Param | Example | Description |
|-------|---------|-------------|
| `month` | `2025-10` | Filter to a specific month |

---

### `GET /api/campaigns`
Returns campaign-level data with optional filters.

**Query Parameters:**
| Param | Example | Description |
|-------|---------|-------------|
| `channel` | `Email` | Filter by channel name |
| `min_roas` | `3.0` | Minimum ROAS threshold |
| `max_roas` | `8.0` | Maximum ROAS threshold |

---

### `GET /api/insights`
Returns AI-generated recommendations.

## Design Decisions

### Frontend: React via CDN (No Build Step)
Using React 18 + ReactDOM from Cloudflare CDN and Chart.js for visualisations means **zero build tooling** (no Webpack, Vite, or npm on the frontend). The entire frontend is a single `index.html` file that works in any modern browser. Tradeoff: no JSX (uses `React.createElement` directly); suitable for this project scope.

### Dark Theme Analytics Aesthetic
The dashboard uses a dark (`#0a0a0f`) background with a purple accent system (`#7c3aed`) — purpose-built for analytics use cases where data density and contrast matter. Inspired by tools like Linear and Vercel dashboards.

### API_BASE Auto-Detection
The frontend detects whether it's being served from the backend (same origin) or opened standalone (via `file://` or live-server on port 5500) and adjusts the API base URL accordingly — no config change needed.

### MySQL over MongoDB
The data is highly structured and relational; SQL aggregations (SUM, AVG, WHERE filters) are natural fits. MySQL 8 supports JSON columns if future schema flexibility is needed.

### Controllers Pattern
Each resource has its own controller file, keeping route handlers focused on HTTP concerns while DB logic is encapsulated. Scaling to a model layer (e.g., with an ORM like Sequelize) is straightforward.

## Known Issues & Limitations

- **Authentication**: Not implemented (bonus). All API endpoints are public.
- **No real-time refresh**: Dashboard data is static until the DB is re-seeded.
- **React createElement verbosity**: Without JSX compilation, component code is more verbose than typical React projects. A Vite setup would solve this if the project grows.
- **overall_cpc**: Computed as spend/conversions from the channels table aggregate (same as CPA) due to absence of a raw clicks total in the channels table. For production, store raw clicks in the channels table during import.
